# C1: commands-split
Status: draft   ·   Changelog at the bottom

## Summary
`audio_processing/commands.rs` (one 2,666-line file after `cargo fmt`) becomes
the `commands/` directory laid out in README §3.5, rewritten to the §1.3
conventions as it moves. Afterwards: one error enum (`CmdErr`), `&str`
parsers, a `Parsed` result and the new `submit`, a `HELP` table per family
file, a shared `-t` tempo-spec parser instead of four hand-rolled copies, and
mirror lookups as `EngineState` methods. User-facing command syntax and
engine behaviour are unchanged. All 44 existing tests are ported; none are
dropped.

Line numbers below are for `integrate/wave-1` @ `a86c524` (after
`cargo fmt`, before the rest of scaffold step 0). The implementer re-reads
them on the scaffolded branch.

## Registry entries
No pre-wave stubs. C1 changes two signatures that code outside its ownership
calls (`parse` now takes `&str` and returns `Parsed`; `submit` takes `&str`
and returns `Result<Option<String>, CmdErr>`). These edits can't be stubbed
before C1 lands, because they don't compile against the old signatures. So
they are **integration edits**. C1 makes them in one separate commit that the
architect reviews at merge (REQ-024 asks to confirm this; the alternative is
that the architect replays them). Exact edits:

1. `runtime.rs:127-133` (the `Key::Enter` arm):
   ```rust
   match cmd_processor.submit(&cmd, &queue) {
       Ok(Some(text)) => println!("\n{text}"),
       Ok(None) => (),
       Err(error) => {
           buf.clear();
           println!("\nErr: {error}");
       }
   }
   ```
2. `test_util.rs:59-64` (`run`): match on `Parsed`, and add `Parsed` to the
   `commands::{…}` import:
   ```rust
   match cp.parse(cmd) {
       Ok(Parsed::Engine(command)) => conductor.apply(command),
       Ok(Parsed::Local(_)) => (),
       Err(error) => panic!("'{}' failed: {}", cmd, error),
   }
   ```
3. `processes.rs:214-217` (test `setup`): the same shape as item 2
   (`c.apply(command)`), plus `Parsed` in the test module's `commands::{…}`
   import.
4. `engine.rs:1412, 1432, 1437, 1487` (tests): `cp.parse("…".to_string())`
   becomes `cp.parse("…")`.

Nothing else outside `commands/` needs to change: `engine.rs`'s
`use commands::*` and `runtime.rs`'s `commands::{CmdProcessor, CmdQueue,
EngineState}` resolve through the re-exports in step 1.

## Interfaces
**Provides** (all in `commands/`, re-exported from `commands/mod.rs`):
```rust
pub enum Command { Load(LoadArgs), Start(StartArgs), Pause(PauseArgs), Resume(ResumeArgs),
                   Stop(StopArgs), Unload(UnloadArgs), Velocity(VelocityArgs), Group(GroupArgs),
                   Tc(TcArgs), Seq(SeqArgs), Quit(QuitArgs) }        // unchanged
pub enum Parsed { Engine(Command), Local(String) }
pub struct CmdProcessor { pub engine_state: EngineState }
impl CmdProcessor {
    pub fn new(engine_state: EngineState) -> Self;
    pub fn parse(&mut self, line: &str) -> CmdResult<Parsed>;
    pub fn submit(&mut self, line: &str, queue: &CmdQueue) -> Result<Option<String>, CmdErr>;
}
pub enum CmdErr { TempoFormatting, Formatting { err }, MissingArg { arg, cmd }, InvalidArg { arg, cmd },
                  AlreadyIs { ty, name }, NoCmd { cmd }, NoItem { ty, name },
                  NoVoice { name, group }, QueueFull }   // + Display + std::error::Error
pub type CmdResult<T> = Result<T, CmdErr>;
pub const HELP: &[(&str, &str)];   // in each of voice, group, tempo, track, process, procs::seq
```
`Idx`, `TempoRepr` (fields stay `pub`), every `*Args` struct and
`EngineState::new(files: Vec<AudioFile>, out_channels: usize)` keep their
current shapes, so the engine compiles untouched.

**Consumes:** `blast_time::blast_time::{TempoMode, TempoUnit}`,
`blast_rand::{X128P, fast_seed}`, `blast_macros::var_args`,
`file_parsing::decode_helpers::AudioFile`.

**Contract issues:**
- README §3.5 types `submit`'s queue as `&mut CmdSender`. Until R1 it's
  `&CmdQueue` (brief).
- No command produces `Parsed::Local` yet (INS adds `ls`/`help` in wave 3).
  `submit` still checks for a full queue *before* parsing (the mirror
  invariant), so a `Local` command fails while the queue is full. That's
  harmless until R1's rtrb sender, and R1 revisits it.

2. **One error enum, `&str` everywhere, `Parsed`, `submit`.**
   - `errors.rs`: replace `cmd_errors!` with a hand-written
     `#[derive(Debug)] pub enum CmdErr` (same variants and fields, plus
     `QueueFull`), its `Display` with today's messages verbatim (`QueueFull`
     prints `Command queue full`, today's string), and
     `impl std::error::Error for CmdErr {}`. Delete `StateErr` and
     `StateResult`. **Decision:** one enum is enough. `StateErr` was an
     identical copy converted 1:1 by `From`, and nothing matches on it.
     Add two constructors to cut the boilerplate:
     `CmdErr::missing(arg: &str, cmd: &str)` and `CmdErr::invalid(arg: &str, cmd: &str)`.
   - Every `try_*(&mut self, args: String)` becomes `args: &str`.
   - `mod.rs`: add `pub enum Parsed { Engine(Command), Local(String) }`.
     `parse(&mut self, line: &str) -> CmdResult<Parsed>` splits with
     `line.split_once(' ').unwrap_or((line, ""))` (the same split as today's
     `splitn(2, ' ')`, so an empty line is still `NoCmd { cmd: "" }`) and
     wraps each arm's `Command` in `Parsed::Engine`.
     `submit(&mut self, line: &str, queue: &CmdQueue) -> Result<Option<String>, CmdErr>`:
     ```rust
     if queue.is_full() { return Err(CmdErr::QueueFull); }
     match self.parse(line)? {
         Parsed::Local(text) => Ok(Some(text)),
         Parsed::Engine(cmd) => {
             // can't fail: this thread is the only producer, and the
             // queue had room before parse
             queue.try_push(cmd).map_err(|_| CmdErr::QueueFull)?;
             Ok(None)
         }
     }
     ```
   - `queue.rs`: `try_push` returns `Result<(), Command>` (hands the command
     back) instead of `Result<(), String>`.
   Commit `commands: one error enum, &str parsers, Parsed and submit`, then
   the integration edits in their own commit (see above).

4. **Shared tempo-spec parser** (`tempo.rs`). Today `-t` is parsed four
   times (`try_load` `:428-507`, `try_group` `:633-697`, `try_tc`
   `:833-861`, `try_seq` `:915-979`), with slightly different rules. Add:
   ```rust
   pub(super) enum TempoSpec<'a> { New { unit: TempoUnit, interval: f32 }, Context(&'a str), Group(&'a str), Voice }
   pub(super) fn parse_unit(u: &str, cmd: &str) -> CmdResult<TempoUnit>;      // s|m|b, else InvalidArg
   pub(super) fn parse_tempo_spec<'a>(spec: &'a str, cmd: &str) -> CmdResult<TempoSpec<'a>>;
   ```
   `parse_tempo_spec` follows `load`'s rules: `v` (exactly) is `Voice`;
   `c:<name>`/`g:<name>`; a missing name or interval is `MissingArg`; an
   unknown unit or a bad number is `InvalidArg`; parts after the second are
   ignored. Each caller keeps its own extra rules, so every tested error
   variant stays the same:
   - `load`: rejects `Voice` (`InvalidArg`, as today, where `v` isn't a unit).
   - `group`: rejects `Group` and `Voice` (`InvalidArg`).
   - `seq`: first, if `spec != "v"` and `spec.split(':').count() != 2`,
     returns `TempoFormatting` (today's check at `:925-936`).
   - `tc`: the positional tempo first gets the same 2-part check
     (`TempoFormatting`), then rejects `Context`/`Group`/`Voice`
     (`InvalidArg`).
   Two tiny edge cases change and are accepted: `seq -t v:a:b` was read as
   `v` and is now `TempoFormatting`; and the `cmd` label inside some error
   messages is normalised to `<cmd> -t` (e.g. `load -t c:???` becomes
   `load -t`). Both are listed as deviations in the report.
   Also in `tempo.rs`: `TempoRepr` derives `Clone, Debug, PartialEq` and loses
   its inherent `clone` (callers such as `engine.rs:284`
   `TempoRepr::clone(&…)` still resolve, to `Clone::clone`). `clone_owner`
   is renamed `shared(other)` and `clone_from` is renamed
   `following(other, owner_idx)`, since the old names shadow `Clone`'s.
   Commit `commands: one parser for -t tempo specs`.
