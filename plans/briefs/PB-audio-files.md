# PB: Audio files (F1, LOAD, TRK)

## F1: decode-adapter (wave 1)

Implement README §3.2. `file_parsing/` becomes a thin layer over symphonia
plus two small hand-written formats.

- **`symphonia.rs`.** Probe with an extension hint, take the first audio track,
  decode every packet into an interleaved f32 `Vec`, and fill `AudioFile`
  (rate, channels, bits, and `channel_layout` from symphonia's channel
  bitmask). Read symphonia 0.6.1's actual API from the registry source (see
  `roles/planner.md`); 0.6 changed a lot from 0.5.
- **Gapless.** Trim encoder delay and padding for MP3/AAC, and check it works
  for a loop sample (decoded length matches the source length, within a
  documented tolerance).
- **Errors.** Map symphonia errors onto `DecodeError`. A corrupt packet in the
  middle of a file: skip it or fail? Recommend one. A malformed file must
  never panic.
- **`raw.rs`.** Filename convention and `decode_with(name, bytes, RawSpec)`
  (README §4 item 5). Specs: s8/u8, s16/s24/s32 with le/be, and f32/f64 with
  le/be. The track name strips the spec suffix.
- **`au.rs`.** Big-endian header and data offset. Encodings 1 (µ-law), 2–5
  (PCM 8/16/24/32), 6/7 (float/double), and 27 (A-law). Size `0xFFFFFFFF`
  means "to end of file". The G.711 tables are a few lines each.
- **Ordering.** `decode_file` checks `raw`/`au` before symphonia, by magic
  number or extension.
- **Deleting the old parsers.** Delete `wav.rs`, `aiff.rs`, `mpeg.rs` and the
  `decode_helpers` conversion functions. **Before deleting them**, port their
  edge-case tests (odd chunk padding, chunks out of order, `data` before
  `fmt`, streamed data size, truncated files, AIFF SSND offset, extensible
  subformats, 8/24/32-bit, float) into adapter tests that feed the same
  synthetic bytes to `decode_file`. If symphonia rejects a case the old parser
  accepted, list it for the user rather than silently dropping it. The
  `wav_bytes`/`aiff_bytes` builders in `file_parsing/mod.rs` tests are worth
  keeping as shared test helpers.
- **Fixture smoke tests.** One fixture per supported codec, generated by ffmpeg
  (`-c:a flac`, `libmp3lame` or ffmpeg's native mp3, `aac`, `alac`,
  `adpcm_ima_wav`, `adpcm_ms`, `pcm_alaw`, `pcm_mulaw`, aiff `pcm_s16be`,
  aifc `sowt`). For lossless codecs, compare samples exactly against the
  source WAV. For lossy ones, check length and RMS against ffmpeg's own
  decode. Skip when a fixture is missing.
- **Speed.** Decoding a 3-minute MP3 in a release build should take well under
  a second. Measure it.
- `load_assets` keeps its signature and behaviour; it just calls `decode_file`.

## LOAD: load-pipeline (wave 2)

Implement README §3.3:
- **`scan_assets`.** Probe each file for rate and channels without decoding
  it fully.
- **`load_assets`.** Decode, resample and remap. Keep the old `load_assets(dir)`
  working as a wrapper until R1 rewires startup in wave 3, since LOAD doesn't
  own `main.rs`.
- **`resample`.** Use rubato with high-quality sinc parameters (it runs offline
  at load time). State the parameters and the expected quality. Include a sine
  test with a measured error bound. Check that rubato 5's API takes
  interleaved or planar data and plan the conversion.
- **`remap`.** Mono to stereo duplicates the channel. More than 2 channels down
  to 2 is a downmix using `channel_layout`, with ITU-R BS.775 coefficients.
  VOX's pan (wave 3) replaces the engine's mono hack. Say who handles mono
  sources so they aren't handled twice. Recommendation: LOAD leaves mono tracks
  as mono, and VOX pans them.
- **Rate and channel choice.** Prefer the most common rate. The channel count
  is the max over all files, capped at what the device offers.
- **Recursive asset directories.** Propose a track naming scheme for nested
  files and flag it for the user (README §4 item 7). `.` is already the
  `group.voice` separator.
- Duplicate names: same rule as today. Recursion makes clashes more likely.
- Parallel decoding with `std::thread::scope` if loading many files is slow.
  Measure before deciding.

## TRK: runtime-tracks (wave 3)

- **`import <path> [as <name>] [--fmt <spec> --rate <hz> --ch <n>]`.** The
  flags apply to raw PCM only. Decode, resample and remap off the audio thread,
  insert a `TrackRepr` into the mirror (IDs from E1's allocator), and send
  `Arc<[f32]>` to the engine. Decide between decoding on the REPL thread (with
  a "loading…" note) and a loader thread with a completion event. Recommend
  one; a long MP3 can take a moment.
- **`rescan`.** Import new files from the assets dir.
- **`drop <track>`.** Rejected while a Voice uses the track (or forced with
  those Voices stopped). Freed through the garbage queue.
- After E1, tracks have IDs, so the old fragile coupling between the
  `HashMap` iteration order in `Conductor::prepare` and in `EngineState::new`
  should be gone. Verify that, and don't reintroduce it.
