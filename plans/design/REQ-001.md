# Design REQ-001: the recording pipeline (README §3.10)

Architect, 2026-10-24. Status: **approved by the architect, awaiting the user.**
Inputs: `requests/REQ-001-rec-pipeline.md`, `briefs/PJ-recording.md`,
`detailed/RECa.md`, `detailed/RECb.md`, and the rtrb 0.4.0 and hound 3.5.1
sources.

## Problem

REC records the engine's output to WAV. To do that it needs:
- a queue from the audio thread to a writer (the recording ring),
- a thread that writes the file,
- a way to get the ring's producer into the engine and back out,
- engine-to-REPL notices.

README §2 counts a new thread or queue as architecture-weight, and §3 has no
recording section. The brief already prescribes the shape (an rtrb ring and a
writer thread). What remains is to fix the exact contract, so that E1 (wave 2)
and R1 (wave 3) leave the right hooks, and the wave-4 scaffold has exact stubs.

## Options

1. **Ring per take, writer thread per take, producer moved in by a `Command`
   and out by the garbage queue, plus a notifier and a shutdown join**
   (the planner's proposal).
   - Cost: what the brief already asks for. It adds two requirements on E1
     (the garbage push hands the value back when the queue is full; garbage
     can carry non-`Copy` payloads) and two on R1 (a line printer that any
     non-audio thread can call; a quit path that drops the stream, then
     joins the writers).
   - Real-time path: `push_entire_slice` (a wait-free copy into
     preallocated slots, `rtrb/src/chunks.rs:307`) and `is_abandoned` (one
     atomic load).
2. **Writer reports through the engine's event queue.** Rejected: the queue
   is SPSC (engine to REPL), and a second producer would need a lock or a
   second queue.
3. **Option 1 without the notifier.** One registry line cheaper. But disk-full
   and I/O errors stay silent until the user types `rec`, which is bad for a
   multi-hour take.

## Recommendation: option 1, with four amendments

1. **No free on the audio thread, ever.** RECb's last resort (all four
   `retiring` slots full) must `std::mem::forget` the producer, a leak of at
   most one ring, instead of dropping it. Dropping could free the ring
   on the audio thread if the writer has already exited. The case needs five
   stops in a row while the garbage queue stays full, so a leak is the right
   trade, documented in a comment.
2. **Tests never call `export::finish_all`.** It stops every live writer in
   the process, so it would interfere with other tests running in parallel.
   Test the stop flag through `RecHandle::request_stop`. `finish_all` is
   exercised only by the runtime quit path and the manual check.
3. **`Command` stays move-only.** `RecStartArgs` carries an
   `rtrb::Producer<f32>`, which is `Send` but not `Clone`. No plan may require
   `Command: Clone` or `Command: Debug`. (`Command::Batch` rollback, if any,
   snapshots the mirror, not commands.) E1 checks this when it removes the
   `unsafe impl Send/Sync` for `Command`.
4. **The clock advances inside `render`.** The global sample clock is
   advanced per frame inside the Conductor's render loop, as it is today
   (`engine.rs:98`), not by the backend. RECb's tap and RECc's bounce rely on
   `render` being the only thing that moves time.

## Exact README changes (applied only after the user approves)

**§3.4, append to the queues bullet:**
> The garbage push never drops on the audio thread. When the queue is full, it
> hands the value back (`fn discard(&mut self, g: Garbage) -> Result<(), Garbage>`)
> and the caller parks it and retries next period. `Garbage` variants may
> carry non-`Copy` payloads (boxed objects, `rtrb` producers). `Command` is
> move-only (`Send`, not `Clone`). The sample clock is advanced only inside
> `render`.

**New §3.10 Recording (REC, wave 4):**
> - `export::start(path, RecSpec) -> Result<(rtrb::Producer<f32>, RecHandle), RecError>`
>   runs on the REPL thread. It creates the file (path errors return
>   synchronously), allocates an f32 ring of 4 s × rate × channels, and spawns
>   one writer thread (`blast-rec`) per take. The writer turns the ring into
>   WAV through `hound`: 32-bit float by default, or 16/24-bit with clamping
>   and TPDF dither done on the writer thread. It checkpoints the header every
>   second and splits into numbered files before the 4 GiB WAV limit (REQ-003).
> - `Command::RecStart(RecStartArgs { producer })` and
>   `Command::RecStop(RecStopArgs {})`. The Conductor's `RecTap` pushes each
>   rendered block, after mixing and before the backend clamps, with
>   `push_entire_slice`. When the ring lacks room, it drops the whole block
>   (counted). It never blocks, allocates or frees.
> - End of take: the producer leaves the engine through
>   `Garbage::Recorder(Producer<f32>)`, either on stop or once the writer is
>   gone (`Producer::is_abandoned`). The REPL side drops it, and the writer sees
>   `Consumer::is_abandoned`, drains what's left, finalises, and exits. A
>   `stop` flag set by `export::finish_all(timeout)` is the fallback at quit.
> - Events (`Copy`): `RecDropped { samples: u32 }` (one per overflow
>   episode), `RecAborted` (writer gone), and `BounceDone { frames: u64 }`
>   (REQ-002).
> - Runtime hooks: `export::set_notifier(fn(&str))` is called once at startup
>   with a line printer that any non-audio thread may call. The quit path
>   calls `export::finish_all(Duration::from_secs(5))` after dropping the
>   audio stream.

## Effect on ownership and registry

There are no ownership changes. The wave-4 scaffold adds RECb's registry
entries 1–12. Entry 11 puts two lines in R1's runtime files (the notifier at
startup and `finish_all` in the quit path). In wave 4, REPL owns
`runtime/repl.rs`. If R1 puts the quit path there, the scaffold lines land in
REPL's file before REPL starts, and REPL must keep them. I'll name the exact
file when scaffolding wave 4.
